TASK 2. CHECK THESE LEADS FIRST (from the 27 October analysis)
  a. jpl-derived-points.js is 5.2 MB of source, inlined into app.html. On
     main its global, window.JPLDerivedPoints, is read in exactly two
     places: planetaryNodeOf() and the lunar apogee, which the expanded
     chart uses and Today does not. That makes it the strongest deferral
     candidate. Model the loader on how gazetteer-world.js (7.3 MB) is
     already loaded only on demand, show "Loading" in the expanded chart
     until it arrives, and cache it on first use the way the gazetteer is:
     in the service worker's runtime cache, never in its install time
     precache. A file in the precache is downloaded at install by every
     visitor, which would cancel the saving; that is why gazetteer-world.js
     is deliberately left out of it (CLAUDE.md, "The world place list is
     fetched when a birth place is asked for").
  b. The next largest: comet-integrated-jpl.js (0.7 MB),
     minor-body-elements.js (0.3 MB), comet-hyakutake-jpl.js (0.2 MB). Find
     which of them Today, the registration card and the first run need.
  c. modulesReady() waits for InCommonCore, PracticeLibrary, ProfileManager,
     SabianSymbols, Astronomy and LunarMeanPoints. boot() polls it every
     150ms. Check whether the first screen needs all six, and whether a
     shorter poll or an event would save time. boot() is shared with
     workstream 3: describe a change there on the pull request rather than
     making it.
  d. Fonts: compare Google Fonts against "node tools/build-bundle.js --fonts
     self", on first visit and repeat visit.
  Classify a, b and d as "safe now"; c touches boot and needs workstream 3's
  agreement first.

HARD RULES (in addition to your brief's)
  - Anything deferred is cached on first use, never precached at install,
    and every screen that needs it keeps working offline once it has been
    opened online. Prove it by opening those screens once online, then
    offline. A deferred file never opened online is honestly unavailable
    offline: the screen shows its Loading state or an honest message.
  - A deferred module that fails to load leaves the screen on its Loading
    state or an honest message, never blank.
  - One change at a time, measured before and after, five runs each,
    median reported. Revert anything that does not improve a number.
