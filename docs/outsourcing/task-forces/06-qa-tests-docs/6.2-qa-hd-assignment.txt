THE OUTCOME
Every Human Design improvement after this is measured against a fixed set of
reference charts, and the honesty rules (no silent fallback, every sub line
value with its confidence) are rows that go red when broken.

TASK 1. REFERENCE CHARTS
  tools/fixtures/hd-reference.json and tools/check-hd-reference.js.
  a. Twenty to thirty charts: births whose data is public and well sourced
     (historical figures with recorded birth times, Rodden AA or A where
     available), plus synthetic edge cases you construct: a birth on a DST
     change, a fractional offset zone, the far north, a Sun within a tenth of
     a degree of a gate boundary, a Moon within a hundredth of a line
     boundary, no birth time, a century boundary. No private person, and
     nothing taken from a user.
  b. For each: the expected Type, Authority, Profile, defined centres,
     defined channels, and the 26 activations to gate and line. Expected
     values come from at least two independent public calculators. Where
     they disagree with each other or with inCommon, the fixture records
     the disagreement and its cause (zone revision, boundary crossing,
     calculation convention), and the row asserts inCommon's documented
     answer. A disagreement nobody can explain fails the row. For a
     convention, cite the note in 1.3's vault (data-contracts/hd-vault/
     Verification/) that settles it rather than writing the convention out
     again; if 1.3 has not settled it, say so and ask on the Task Force 1
     pull request.
  c. The check runs inCommon's own code (lift it the way
     check-astral-bodies.js does), needs no browser, and joins the fast
     gate list (6.1's run-gates.js).
  d. These charts are also 1.3's fixed cases: once the fixture lands, post
     on the Task Force 1 pull request so 1.3's reconciliation script can run
     over it. 1.3 and this check then read the same charts.

TASK 2. HONESTY ROWS (with workstream 3, as 3.2 lands)
  Rows for each of 3.2's Task 2 cases: the arc solver removed, a Sun
  missing, an impossible profile pair. Each asserts the chart says what was
  approximated or is unavailable, and each is shown red against the code
  before 3.2. For 3.2's Task 4 (Color): boundary sweeps, and a row that
  moves the birth time by a minute and expects the Moon's confidence to drop.

TASK 3. THE BENCHMARK PROTOCOL (docs only)
  docs/hd-upgrade/03-benchmark-protocol.txt: the study that decides whether
  inCommon has doubled Ra.TV and Maia Mechanics. About 30 participants
  across beginner, student and practitioner; counterbalanced task order;
  learning tasks against Ra.TV and chart tasks against Maia at comparable
  tiers. Define each measure in 01-competitive-study.txt section 6 exactly
  (what is timed, what counts as correct, how errors at seven days are
  scored), the consent wording, and what data is kept. Nothing is run until
  the owner decides recruitment and budget (delegation plan, D5).
