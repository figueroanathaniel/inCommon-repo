Key finding
The core emits zero interpretations. Every public function returns numbers, arithmetic traces, statuses, or validation verdicts. All meaning-language lives one layer up — in the prototype's static UI copy (demo-labeled) or in Stella's live replies (validator-gated). Exactly one core string is user-facing prose: the fixed birth-time caveat in deriveVisibility().note. Consequence for memory design: core outputs may be stored as facts; UI interpretation text must never be stored as if it were calculated.

2 · Where calculation ends and interpretation begins
Three bands. The core occupies only the first; the work strings it returns (e.g. “7 + 2 + (1992→3) = 12 → 3”) are arithmetic show-your-work, not meaning.
Band 1 — Calculated
incommon-core.js
Numbers, digit traces, statuses, verdicts. Deterministic; fixture- and vector-tested; versioned (v1.2.0). No adjectives, no advice, no personality claims.
Band 2 — Interpretation
Prototype UI layer (static)
Digit-theme blurbs (DIG map), screen copy, scripted Stella branches (canned()), assessment text. Fixed strings, demo/illustrative-labeled. Never generated by core.
Band 3 — Synthesis
Live model (Stella)
The only place free text is generated. Constrained by the grounding prompt and by core guardrails: citation validation, history filtering, sanitizer, output crisis check, timeout.
